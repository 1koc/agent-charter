# todo/README.md —— 演进方案索引

> **本目录 = 层 B 活文档**，存放**进行中 / 待实施**的演进方案，**一方案一文件**。
> 方案落地后：移入 `doc/archive/`（命名 `yyyy-MM-dd-HH-mm-原名.md`）→ 从本表删行 → 新建 ADR（见 `index.md` §6）。
> **调研类文档不进本目录**（落 `doc/research/`）；**未解决尾巴不进本目录**（落本目录 `遗留问题.md`）。

---

## 一、在办方案

| 文件 | 一句话 | 状态 | 阶段/闸门 | 依赖 |
|---|---|---|---|---|
| `{{YYYY-MM-DD-主题.md}}` | `{{做什么 + 做到什么程度}}` | `{{设计中 / 待裁决 / 实施中}}` | `{{批 N / 待门禁 X}}` | `{{前置方案}}` |

**状态取值**：`调研中 → 设计中 → 待裁决 → 实施中 → 待验证 → 已落地（转 archive）`。

---

## 二、方案文件必备骨架

> 缺项方案不得进"待裁决"。**目的是让接手的人不用问人就能推进**。

```markdown
# <方案名>

> 状态：{{设计中/待裁决/实施中}} ｜ 成熟度：{{结构已立/已实测}}
> 上游依据：{{调研件路径}} ｜ 关联 ADR：{{#N}}

## 1. 目标与非目标        ← 非目标写清，防范围蔓延
## 2. 现状（带 file:line 证据）
## 3. 影响面（文件清单：改哪个 / 为什么 / 回滚方式）
## 4. 设计（类/函数签名/数据模型/时序）
## 5. 决策项（逐条：选项 + 代价 + 推荐 + 理由，按 AGENTS.md §5 六件套）
## 6. 实施批次（批序 + 每批出口验收命令）
## 7. 验收判据（可判定的数字/命令，禁"运行正常"这类）
## 8. 遗留与风险
```

---

## 三、"待裁决"的含义（硬约束）

- 文件里每个决策项都有 **`待表态` 标记 + 期望代号**。
- **未获表态不得动源文件**（回 `AGENTS.md` Rule 1 / 闸 2）。
- 用户给代号后：**回显「你裁了什么 → 我做了什么」**，再进下一批。
