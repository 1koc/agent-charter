# segmented-exec —— 部分全自动执行流程（分段 + 检查点）

> **本文件 = `index.md` §8.6 的配套细则**。规则本体在 `index.md`（常驻），本文件**按需读**。
> **一句话**：大任务切段、段间设检查点、验收过放行；**边界只画在「有客观验收命令」处**。默认**同会话**继续，仅当上下文逼近天花板或步数远超预估时**才切新会话**，且由**人拍板**。

---

## 0. 为什么（成本结构，实测）

| # | 事实 | 推论 |
|---|---|---|
| 1 | 每走一步都要为**前面全部上下文**重付一次"复读费" | 贵在「上下文大小 × 步数」，不在工作量 |
| 2 | 读过的内容再读 ≈ **1/50 全价**（前缀缓存命中） | **冷读**（没读过的大文件）是最贵的动作 |
| 3 | 长任务中"重发税"可占总额度 **44%+** | 分段 + 合批是唯一有效手段 |

---

## 1. 何时分段（判据）

| | 可自验（有客观验收物） | 不可自验 |
|---|---|---|
| **高不确定** | 拆解（人来拍板） | 拆解 |
| **低不确定** | **连跑最省** | 拆解（需刹车） |

- **触发**：预期步数 **≳50**（**初值，试用后校准**）且可切段 ⇒ 分段执行。
- **不拆**：< ~20 步；强上下文耦合（同一 bug 连续推理）；机械改写且无可自验出口。
- **反例**：编译 / 任务编排 —— 无独立性，拆了更贵。

---

## 2. 分段模板（R0–R4）

| 段 | 内容 | 出口验收物（硬） |
|---|---|---|
| **R0 调研** | 外部/内部源码探查（只读、集中） | 接口对照表（一页 `.md`，落 `doc/research/`） |
| **R1 契约** | 接口 / 数据结构 / 枚举 + 契约单测骨架 | 契约单测通过 |
| **R2 实现** | 主逻辑 + 接线 + 单测 | 编译过 + 全量单测过 |
| **R3 e2e** | 部署 + 探针 / 替身驱动 + 实证 | e2e 日志（可判定数值） |
| **R4 归档** | 交接件 + 索引 + 遗留 + ADR | 文档闭环 |

> 按任务裁剪段数；**边界须落在验收命令处**。

---

## 3. 检查点协议

1. **段出口**：跑一条验收命令；结论写进 **artifact（文件）**，不靠对话记忆。
2. **段入口**：新段入口只贴「系统提示 + 索引 + 本段简报（≤1 页）+ artifact 指针」，**不带上一段全文**。
3. **形态（默认同会话；越界才切新会话）**：
   - **默认同会话继续**：零额外人工；段间"重置"仅**纪律性收束**（写简报、丢旧上下文）——注意**同会话无法真正清空历史**，上下文仍累积、**重发税省不掉**。
   - **切新会话（真省）**：仅当 ① 上下文逼近天花板，或 ② 步数**远超**预估、任务确实变大时，**切段 → 另开新会话**，只粘 1 页简报 + artifact 指针。代价是**人工往返**。
4. **谁拍板**：助手**只提示不自行切** —— 已做步数超 **~30**（初值）或上下文明显逼近天花板时，**主动提示"建议设检查点 / 切新会话"**，由**人拍板**。
5. **放行**：验收过 ⇒ 同会话内可直接进下一段；需切新会话时，产出「下一段启动简报」（1 页）**由人开新会话粘贴启动**（**不存在"自动进下一段"**）。不过、或命中「不可自验」⇒ **停下报批**（Rule 1）。

## 4. 检查点简报模板（1 页，可复制）

```markdown
# 段 R2 简报
- 段名：R2 实现
- 出口验收命令：{{构建命令}} && {{测试命令}}
- 验收结果：编译 0 error / 测试 25/25 通过
- 产物指针：build/ctest.log
- 本段产出：<新增 / 改动文件清单>
- 决策与理由（一行）：<关键取舍 + 为什么>
- 下一段入口需要：<最小上下文>
```

## 5. 两个优先杠杆

1. **R0 调研前置**：外部源码探查集中成一段、产物落一页表 ⇒ 后续段读表不读源码（直击长上下文探查 ~41%）。
2. **R1 契约单测前置**：类型/接口错在**编译期**拦，不在运行时暴雷（直击「单测码被改 15 次」的返工病根）。

---

## 6. 与既有规则的关系

- **不替代 Rule 1**：「不可自验」处仍是**停下报批**。
- **不替代 §8.3**：§8.3 管跨仓留痕；本条管**执行切分与成本**。
- 与历史方案中反复出现的 **S0→S4 惯例**同一思想（本条是**成本门控**复用）。

---

## 7. 反噬提醒（miss 比 hit 贵 50×）

- artifact 必须 **≤1 页**，禁长报告（冷读大文件 = 高单价 miss）。
- 工具调用**能合批则合批**：并行读多文件 / 多处检索合为一步，减少串行往返（每多一步 = 多付一次上下文重发）。
- 目标：段内上下文降到 **~85K/步**（基线常量为 155K/步）。

---

## 8. 验证判据

1. **流程合规**：任一 ≳50 步任务能答出「段数 + 每段出口验收命令」。
2. **成本改善（对账，非闸门）**：用同一口径对比同规模历史轮；**偏离估算 ±10% 内视为一致**，显著偏离则修订阈值。**不作 pass/fail**。
3. **不劣化交付**：验收判据不减少、返工步数不增加。

---

## 9. 写这类规则的三条教训（血泪）

1. n=1 的估算只能标「初值待校准」，**不能当 pass/fail 闸门**。
2. 「验收过自动放行」与「跨会话分段」**互斥**（跨会话必须有人接力），别写出自相矛盾的条文。
3. 事前估不准步数 ⇒ 必须补「中途变大在哪设检查点」的规定。
