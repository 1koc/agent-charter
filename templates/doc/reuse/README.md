# reuse/ 索引 —— 可复用经验与可演进范式

> **本目录是什么（规则见 `index.md` §8.7）**：**层 B 活文档**，收录**已在本仓或他仓用过、值得复用**的经验、规范与协作范式。**它不是冻结区** —— 记录的是*当前有效口径*，须随实践演进更新；失效结论保留原文并标注指向新结论，不静默删除。
>
> **与相邻目录的分工**：
> - `doc/todo/` = 演进**方案**（一次议题一份，落地后进 `doc/archive/`）
> - `doc/research/` = **前置调研**（只读取证、结论型，为立项做依据）
> - `doc/reuse/` = **沉淀复用**（已验证或正在验证的可复用机制，跨议题长期有效）
>
> **准入门槛**：须**已用过至少一次**；纯设想先落 `doc/todo/` / `doc/research/`，用起来再沉淀。

## 双源机制（写新件前先判类型）

| 来源 | 形态 | 特征 | 落点要求 |
|---|---|---|---|
| **① 经验归档型** | 从**已发生**的实践中提炼 | 须有**实测证据**（行号/命令输出/编译结果）；结论已基本稳定 | 一条机制 = 一句话结论 + 为什么 + 复现动作 |
| **② 范式构建型** | **先立结构**，边用边完善 | 结构已立但**实践未走完**；须显式标注**待验证区** | 头部标「**构建中**」，写明**升级条件**与**首个实践对象** |

**②不是①的前置或替代**：一次实践走完前，①**无法从零**总结（结构尚未被现实检验）⇒ 先以②立结构，用它走一遍，走完才沉淀为①。**转段以「升级条件满足」为准**，不由主观判断。

## 每件文件的头部件（强制）

```markdown
# <范式/经验名>

> **成熟度**：构建中（结构已立，实践对象=待填）｜ 已验证（实证 ≥1 次）
> **准入依据**：{{双源机制之 ① 或 ②}}
> **升级条件**（仅"构建中"需写）：{{达到什么就转①}}
> **本文件是方法，不是事实**。与任何代码/现状不一致时**一律以代码为准**（`index.md` §8.1）。
> **实例数据不属本范式**：具体文件行号、编号、项目专有名词一律留在实例文档里，本文件只给「怎么切、怎么判、怎么验」。
```

> ⚠ **最后一条最容易违反**：模板里塞了项目专有内容，就污染了"可复用"语义 —— 这件东西下次只能在同一个项目用，等于没沉淀。

## 维护说明

- **新增**：先确认不属 `doc/todo/`（方案）或 `doc/research/`（调研）；满足准入门槛后在本表加一行。
- **演进**：本目录为活文档，内容随实践更新。**结论翻转时**在原处标注「`YYYY-MM-DD` 更新：原为…，现为…」并给出新结论，**不删历史**。
- **失效**：结构被实践证伪 ⇒ 退回「构建中」并注明「因 X 实践被证伪/不足」；整体失效且无替代 ⇒ 移入 `doc/chaos/` 并从本表移除。
- **状态可逆**：`已验证` 可退回 `构建中`。不得删除历史结论，改为行内 `~~删除线~~` + 指向新结论。
