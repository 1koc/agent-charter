# 采用路线：从零到"驯服完成"，按档位递进

> 这套框架的价值**不在文件齐全，在于每条规则都带真实项目事实**。全套空壳铺开 = 一堆正确的废话，AI 照着它照样走错。
> 所以：**先小后全，先事实后规则**。

---

## 档位总表

| 档 | 产出 | 适用 | 判据（做到就算完成） |
|---|---|---|---|
| **档 0 · 最小可用**（30 分钟） | `AGENTS.md` + `index.md`（含检索表 + 关键路径清单 + 3 条易错区） | 任何新仓，**默认选这档** | AI 只读 `index.md` 能答出「改这里先跑什么、哪里不能碰、错了怎么回滚」 |
| **档 1 · 标准**（半天） | + `doc/` 骨架 + `doc/ref/build.md` + `doc/ref/project.md` 填实 | 有构建/部署链条的仓 | 新人（或新会话 AI）照 `doc/ref/build.md` 能独立跑通一次构建 + 测试 |
| **档 2 · 议题化**（首个方案时） | + `doc/adr/` + `doc/todo/` + `遗留问题.md` 开始使用 | 有≥2 人在改、或要留决策痕迹 | 每条已落地的架构决策都有 ADR，且状态表能答"现在还成立吗" |
| **档 3 · 沉淀化**（跨议题经验出现时） | + `doc/reuse/` 双源 + `doc/research/` + `doc/note/` | 经验开始重复出现、同类问题被反复踩 | 遇到"这个坑好像踩过"能 30 秒内找到对应 reuse/note 件 |

**不要跳档**：档 0 没落地就铺档 3 的目录 ⇒ 空目录变成"文档债"，反而降低信任。

---

## 新仓从零：执行顺序

```
1. 探测事实（只读）
   ├─ 构建系统 / 构建命令 / 测试命令（实跑一次，记时长）
   ├─ 目录真值表（哪个能写、哪个只读依赖）
   ├─ 关键路径（并发 / 契约 / 时序 / 资源分配 / 队列所在文件）
   └─ 外部依赖（引擎/上游路径、版本、禁写范围）
2. 落 AGENTS.md（直接复制模板，纯通用，勿加项目内容）
3. 落 index.md
   ├─ §0 填充清单逐项填 → 填完删本节
   ├─ 检索表按本仓目录改写
   └─ AI 易错区先放 3 条最痛的（宁可少，不可编）
4. 落 doc/ 骨架（全空目录也可，但 README 必须写明各目录放什么）
5. 自检四条（见下）
6. 第一个真实任务跑一轮，把过程里发现的事补回 index.md
```

## 新仓自检四条（不过就别宣布"框架建好了"）

| # | 自检项 | 判法 |
|---|---|---|
| 1 | **可答性** | 让一个**没有本仓记忆**的会话只读 `index.md`，问它"我要改 X，先看什么、跑什么、哪里不能碰" —— 答得出 ⇒ 过 |
| 2 | **常驻不膨胀** | `AGENTS.md` ≤150 行，且**不含**本仓专有名词/路径/编号 ⇒ 过 |
| 3 | **规则可判定** | 随机抽 3 条规则，问"违反它能否被逐项指认" —— 都能 ⇒ 过（有形容词式的 ⇒ 重写） |
| 4 | **命令真实** | `doc/ref/build.md` 里每条命令**实跑过一次** ⇒ 过（凭记忆写的命令是负资产） |

## 已有仓库迁移（最常见场景）

**问题**：已经有 `AGENTS.md`（可能很长、混着项目内容），文档散落，改起来怕动到别人的东西。

**顺序（每步都可独立停下，不留半成品）**：

1. **只读盘点**：现有 `AGENTS.md` 行数、`doc/` 目录现状、有无历史决策记录。
2. **切分而非重写**：把现有 `AGENTS.md` 里的**项目专属内容整段搬**到 `index.md`，**不重新组织措辞**（重写会丢信息）。搬完 `AGENTS.md` 只留通用准则。
3. **加检索表**：`index.md` 顶部加「任务 → 读什么」，先只填**你实际会做的 5 类任务**。
4. **拆分册**：`index.md` 里 >100 行的重参考（构建手册、目录表、领域手册）拆到 `doc/ref/`，L1 留一行指针。
5. **建 AI 易错区**：不要一次写全。**每次 AI 犯错就在此加一条**（现象 → 真相 + 证据 → 后果）。这是唯一会自然生长的节。
6. **规则编号不动**：已有编号（含外部引用）**不得重排**；要改号必须同时改全部引用点，否则历史文档全指向错处。

**迁移期禁忌**：
- ❌ 不要为了"结构整齐"重排规则编号（外部引用 350+ 处会全废）
- ❌ 不要一次性把历史文档全部重分类（先立规则，遇一份归一份）
- ❌ 不要删旧 `AGENTS.md` 内容 —— 搬到 `doc/reuse/old_AGENTS.md` 留档

## 常见失败模式

| 症状 | 根因 | 修法 |
|---|---|---|
| 规则写了一堆，AI 照样走错 | 规则是形容词，不可判定 | 每条改成"违反它能否被逐项指认" |
| AI 反复问同一件小事 | 事实没落文档，只在会话里说过 | 落 `doc/note/`（一要点一 md） |
| 文档越写越多但没人读 | 没有检索表，读一次要全文扫 | 加检索表 + 拆分册 |
| 每次开工都要重新解释项目 | 没有 `index.md`，或它只写了目录没写规则 | 补 §0 填充清单那 8 项 |
| 规则执行几天就松 | 没有自检判据 | 每条补「自检判据」一行（答不出 X 即违规） |
| AI 越步改代码 | 缺动手闸 | 补闸 2：写文件前先问"授权范围含这步吗" |
