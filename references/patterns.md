# 范式库：11 条已在实战中跑过的可复用机制

> 每条格式统一：**解决什么 → 判据（什么情况用）→ 复现动作 → 出处**。
> 出处栏指向原始实例所在仓（`uaisim-collector`），仅作溯源；**复现时抄机制，内容按新项目重写**。

---

## P1 · 决策点交互契约（批次序贯 · 逐项呈报）

**解决什么**：AI 一次抛出五个议题的选项表 → 用户串味、记混、只能笼统说"都行" → AI 自行代裁 → 越步。

**判据**：任何**需要用户做判断**的地方（技术选型、字段增删、实现路径、是否执行、范围界定）。

**复现动作**：
1. 先给**批次总表**（只含：批序 / 议题 / 依赖，**不含选项、不含推荐**）。
2. **只展开第 1 批**，其余写"待第 N 批结束后展开"。
3. 批内每议题**独立成节 + 六件套**（自包含 / 代码原文 / 逐行释义 / 选项目标形态 / 选项后果 / 影响面+回滚）。
4. 每个议题结束给「**推荐 X —— 一句话理由**」（必给，禁"看您"）。
5. 用户给代号后：**回显「你裁了什么 → 我做了什么」**，再问是否展开下一批。
6. **未表态项停在原地**；用户问细节但没给代号 ⇒ 答完后**必须重新要求表态**。

**为什么不能省 4 和 6**：省 4 = 把决策推回给用户（等于没分析）；省 6 = 把"问细节"误读成"同意"，是最常见的越步入口。

**出处**：本仓 `AGENTS.md` §5（纯通用，零修改可迁移）+ `index.md` §8.8 三闸。

## P2 · 大任务分段执行（R0–R4 + 检查点）

**解决什么**：一次"人工拍板、AI 连跑到黑"吃掉近半会话额度，其中 **44%+ 是上下文重发税**。

**判据**：预期 **≳50 步**且**可切段**；`<20` 步连跑更省；强上下文耦合（同一 bug 连续推理）不拆。

**复现动作**：
1. 段边界**只画在有客观验收命令处**（编译过 / 测试过 / e2e 数值），不画在"感觉该停"处。
2. 用 R0 调研 → R1 契约 → R2 实现 → R3 e2e → R4 归档（按需裁剪）。
3. 段出口：跑验收命令 → 结论写进 **1 页简报（artifact）**。
4. 段入口：只带「系统提示 + 索引 + 简报 + 指针」，不带上一段全文。
5. **同会话分段省不掉重发税**；真省 = 另开新会话由人粘贴简报接力 ⇒ **AI 只提示、人拍板**。

**两个杠杆**：R0 产物 = 一页对照表（后续读表不读源码）；R1 契约单测前置（错在编译期拦）。

**细则**：`templates/doc/ref/segmented-exec.md`（可整份复制）。

**出处**：本仓 `index.md` §8.6 + `doc/ref/segmented-exec.md` + 成本实测 `doc/research/2026-10-14-*`。

## P3 · 文档三分层 + ADR 双件套（SSOT）

**解决什么**：代码一动就大面积改文档 → 干脆不改 → 文档腐烂；以及"决策正文"与"当前是否有效"混在一处 → 状态永远写不进去。

**判据**：任何有历史累积记录的仓库。

**复现动作**：
1. 按「是否随代码演进」分三层：**层 A 冻结**（ADR 正文、archive、chaos、origin —— **允许坏链、禁止回填**）/ **层 B 活**（索引、`doc/ref`、`doc/reuse`、`note`、`research` —— **要求 0 坏链**）/ **层 C SSOT**。
2. **SSOT 拆两件**：状态与取代关系只放 `adr/README.md`（活）；决策正文放 `NNNN-*.md`（冻结）。
3. 引用写法优先级 **符号 > 路径 > 行号**；行号只在 ADR 作"当时快照"。
4. `doc/` 根只允许 `README.md`；新增文档先确认归口。

**效果**：把"改代码 → 改文档"从全仓收敛为"仅架构决策/契约变更才动文档"；行号漂移与文件移动**不再触发文档更新**。

**出处**：本仓 `index.md` §8 / §8.1、`doc/README.md`、`doc/adr/README.md`。

## P4 · `doc/reuse/` 双源机制 + 成熟度标记

**解决什么**：经验有两类 —— "已验证的"和"结构已立但还没走完的"，混放会导致**未验证的东西被当成熟经验引用**。

**判据**：要沉淀跨议题长期有效的机制时。

**复现动作**：
1. 分类落盘：**① 经验归档型**（须有实测证据，结论稳定）/ **② 范式构建型**（先立结构，标"构建中" + **升级条件** + **首个实践对象**）。
2. 每件头部**必写成熟度**；状态**可逆**（被证伪 ⇒ 退回构建中，注明"因 X 实践被证伪"）。
3. 结论翻转：原处标注「`日期` 更新：原为…，现为…」，**不删历史**。
4. **准入门槛：已用过至少一次**；纯设想进 `doc/todo/` 或 `doc/research/`。
5. **模板里不得塞项目专有内容**（否则这件东西只能在本项目用，等于没沉淀）。

**出处**：本仓 `index.md` §8.7 + `doc/reuse/README.md`。

## P5 · 总纲 + 子方案拆分（文件级归属矩阵）

**解决什么**：一个议题跨多个共享文件、要分批上线 ⇒ 一起改必撞、一起评审必失效。

**判据**（三条**同时**成立）：① 碰 ≥2 个共享热点文件 ② 各部分**能独立上线且批间双向兼容** ③ 规模大到无法一次评审完。**第 2 条最容易被跳过** —— 若"必须同批上线"，它本质是一个原子改动，硬拆只制造中间态。

**复现动作**：
1. **先测绘再谈并行**（实测，不接受估计）：引用面（`grep -rln`）、汇聚点、构建登记方式（GLOB vs 显式列表）、target 边界。
2. 切子方案 → 填**文件级归属矩阵**（独占写 / 只读依赖 / 公共可读）。**判定：独占写列无交集 ⇒ 可并行**。**只交集一个文件也要串行。**
3. 三招消冲突（**顺序重要，先 B2**）：B2 逻辑不进汇聚点（让热点变 bystander）→ B1 新增件不登记构建 → B3 契约头只增不改。
4. 每子方案**独立 commit**（否则单子方案回滚是空话）；批次门禁含「**源文件不变量**」复核矩阵。
5. 合并冲突 = **矩阵漏判的信号**，禁止就地解冲突，回炉修矩阵。

**出处**：本仓 `doc/reuse/总纲-子方案-复杂议题拆分范式.md`（成熟度=构建中，可当结构参考，勿当已验证结论）。

## P6 · 最小可验证面（只换被测单元）

**解决什么**：工作区混着别人未提交的改动 / 并行分支未收尾 ⇒ 无法干净验证自己的结论，跑出来的现象分不清是谁造成的。

**判据**：共享工作区脏、或需要**在他人改动之上**出自己的结论时。

**复现动作**：
1. 按"被测改动属于哪个**产物单元**"划隔离边界（哪个 DLL / 包 / 服务）。
2. **只替换被测单元**，其余保持部署位原样 ⇒ 变量单一。
3. 先核**共享件**是否含并行实代码（避免被别人的改动污染判据）。
4. 记录旁路产物（临时文件/日志），验证后清理。
5. 结论显式写明"在何种隔离条件下成立"。

**反例**：全量重建后宣布"我的改动没问题" —— 分不清是改了 A 还是 B 带来的变化。

**出处**：本仓 `doc/reuse/L2-隔离验证-单DLL替换.md`（已验证）。

## P7 · 假对端自证（替身驱动，跨仓解耦）

**解决什么**：跨仓/跨端功能，对端排期不受本仓控制 ⇒ 插件侧长期无法独立收敛，只能干等。

**判据**：功能生效依赖**对端配合**（新消息无订阅者、新字段无消费者、新协议对端不认）。

**复现动作**：
1. 本仓**先落自己这侧**（契约 + 生产 + 发布）。
2. 用**替身驱动**充当对端：只做"订阅 + 收帧 + 按契约解析 + 关键命令回写"这几件最小行为。
3. 判据：替身能收到预期消息/帧型/字段，且**字节可解析** ⇒ 本侧 PASS。
4. 记录替身的**行为假设**（心跳频率、重发策略、消费速率）—— 这些是对端策略的**实验变量**，不是猜测。
5. 真实对端接入后，按 §8.3 交接文档验收。

**关键收益**：把"对端行为未知"从**阻塞**变成**实验变量**（可以逐项试：晚订阅、不消费、乱序、断连）。

**出处**：本仓 `index.md` §8.4 + `scripts/verify/fake_java_driver.py`（本仓实现，机制可迁移）。

## P8 · 源码行号漂移核查（Grep 全文复核）

**解决什么**：源文件演进后，文档里的 `file:1204` 全部错位 ⇒ 后续所有基于行号的判断都是错的，且**错得很像对的**。

**判据**：要写入/修订任何**引用具体行号**的内容时。

**复现动作**：
1. 列出目标锚点（函数名 + 注释关键词 + 两种写法 `file.cpp:NNN` / `LNNN`）。
2. **全文 Grep**（不靠"上次偏了 48 行，整体 +48 平移"）。
3. 就近读 10–15 行确认命中是真实现还是 `__except` 包裹体 / 被注释代码。
4. 以**当前实际位置**覆盖文档旧值；历史修订行**保留**（是快照）。
5. 在修订记录新增一行：「以 Grep 全文复核为准 + 漂移根因」；同步校正关联文件的同一锚点。

**预防**：新写作时**优先用符号定位**（`x.cpp :: Func()`），行号只在 ADR 作快照 —— 从源头消掉漂移。

**出处**：本仓 `doc/reuse/源码行号漂移核查.SKILL.md`。

## P9 · 记忆索引式（结论 + 指针）

**解决什么**：AI 工作记忆写满细节 → 每会话注入 = 常驻膨胀 + 与真实文档**双份漂移**。

**判据**：任何跨会话的项目记忆。

**复现动作**：
1. 记忆文件**只写**：结论 / 铁律 / **落点指针**（哪个文档有细节）/ 近期主线一句话。
2. 细节一律落 `doc/`（`knowledge/` 或 `doc/ref/`），记忆里只留链接。
3. 记忆文件**控制在合理长度**（超过就该往外搬）；超出即说明在写文档而不是写索引。
4. 长会话压缩后：**第一件事回读规则原文**（摘要会丢强制语气与编号 —— 见 P1 的闸 3）。

**出处**：本仓 `.workbuddy/memory/MEMORY.md` + `knowledge/`（结论与细节分层）。

## P10 · 无损时基取证（统计只认无损源）

**解决什么**：拿日志文件统计"每帧/每秒多少条" → 日志本身有轮转与丢行 ⇒ **结论结构性错误，且看不出错**（实测某次 85s 跑窗里主日志只剩最后 2 秒）。

**判据**：任何要按帧/按秒/按次的**计数类结论**。

**复现动作**：
1. 先问：**这个数据源会丢吗？**（异步缓冲 / 轮转 / 采样 / `overrun` 策略）
2. 只有无损源才能作计数判据：**同步控制台输出** / **结构化二进制落盘** / **数据库记录**。
3. 日志文件只用于**定性线索**（有没有报错、大致顺序），不用于定量结论。
4. 定量结论必须写明**数据源 + 过滤条件**（如"剔除某类内部记录副本"），否则别人无法复现。

**泛化**：任何"抽样数据"都不能推"全量比例"；任何"客户反馈"都不能推"用户比例"。

**出处**：本仓 `index.md` AI 易错区末条 + `knowledge/工具链陷阱与运行态.md`。

## P11 · 反模式清单（这 12 件事，做了就返工）

| # | 反模式 | 为什么错 | 改成 |
|---|---|---|---|
| 1 | 一次性铺开多个议题的选项表 | 用户串味、只能笼统答 | P1 批次序贯 |
| 2 | 用「是否继续？」结束分析 | 把分析责任推回用户 | 给推荐 + 理由 |
| 3 | 六件套缺「推荐」或「每项代价」 | 决策信息不全，等于没呈报 | 逐项写代价 + 必给推荐 |
| 4 | 把压缩摘要当规则出处 | 摘要丢了强制语气与编号 | 回读原文（闸 3） |
| 5 | 提案通过后连跑实现+编译+跑测+回填 | 每步单看都自洽 ⇒ 无人刹车 | 动手闸：先问"授权范围含这步吗" |
| 6 | 常驻文件里塞项目专属内容 | 每步永久加税 + 跨仓不可复用 | 移 L1/L2 |
| 7 | 同一内容两处维护 | 必漂移 | 链接 + 一句摘要 |
| 8 | 用日志做定量统计 | 有损源 ⇒ 结论结构性错误 | P10 无损时基 |
| 9 | 声称"可并行"但没做文件级矩阵 | 分支跑起来才撞 | P5 先测绘 |
| 10 | 模板里带项目专有内容就宣布"可复用" | 只能在本项目用 = 没沉淀 | 抽掉实例数据 |
| 11 | 全量重建后宣布"我的改动没问题" | 分不清是谁带来的变化 | P6 最小可验证面 |
| 12 | 写规则用形容词（"尽量""注意""适当"） | 无法逐项指认 = 必被稀释 | 写成可判定判据 |
